`cc_heistcontracts` ships four console commands. Three are debug-only (un-restricted) and one is ACE-gated.

## `/heist:grantxp <alias> <amount>`

Grant XP to a profile by alias. Handles level-ups and pushes a fresh profile sync to the recipient if they're online.

```
/heist:grantxp ghost_42 5000
```

| | |
| --- | --- |
| **Restricted** | Yes — `restricted = true` on the registration. |
| **Allowed callers** | Console (source 0), or in-game admins with the `command.heist:grantxp` ACE permission, or the `admin` ace. |
| **Online recipient** | Mutates the cached profile, marks it dirty (next 30s flush persists it), and immediately calls `_G.HeistSync.SendProfile(src)` so the dashboard updates without waiting for the next sync request. |
| **Offline recipient** | Resolves alias → `citizenid` via a single `SELECT`, computes the new level/XP, and updates the row directly. Doesn't pollute the in-memory cache (no owner src). |

### ACE setup

Either grant the dedicated permission:

```
add_ace group.admin command.heist:grantxp allow
```

Or use the catch-all `admin` ace. Built-in superadmins are usually in `group.admin` already.

### Output

```
[heist:grantxp] ghost_42 +5000 XP → level 8, xp 12450 (leveled up from 7)
```

If the alias doesn't exist:

```
[heist:grantxp] failed: not_found
```

Other failure codes: `invalid_amount` (zero/negative), `db` (UPDATE didn't affect any rows).

## `/heist:test`, `/heist:test2`, `/heist:test3`

Three **un-restricted** dev commands that exercise the legacy `StartContract` path against the bundled heists. They each:

1. Create a `cc_lib.Groups` group named `'test'` with the caller as leader.
2. Optionally add a second player as a member: `/heist:test 5` adds source 5 to the group.
3. Call `StartContract` directly — bypassing the slot/purchase/VICE flow and the active-slot tracking.

| Command | Calls |
| --- | --- |
| `/heist:test` | `StartContract('Paleto Heist', { group = 'test', location = { id = 'pinkcage' } })` |
| `/heist:test2` | `StartContract('Fleeca Heist', { group = 'test', location = { id = 'pinkcage' } })` |
| `/heist:test3` | `StartContract('Pacific Heist', { group = 'test', location = { id = 'pinkcage' } })` |

These work as long as the named heist resources are registered. If you don't ship one of them, the matching test command will print `unknown contract` and do nothing.

<Warning>
  These commands are not ACE-restricted in the shipped resource. Anyone on the server can run them. **Either restrict or remove them before going to production.**
</Warning>

A reasonable production hardening:

```lua
RegisterCommand('heist:test', function(source)
    if source ~= 0 and not IsPlayerAceAllowed(source, 'admin') then return end
    -- ...existing body...
end, true)
```

Note that `StartContract` bypasses the entire slot system — the player gets the heist's `entry_point` called directly without `activeSlot` being set, so `FinishContract` will return `'not_active'` for them. That's fine for one-off testing, but don't wire production gameplay through it.

## Resetting a profile (manual)

There's no command for this — it's straight SQL:

```sql
DELETE FROM heist_profiles WHERE citizenid = 'ABC12345';
```

The next time the player opens the dashboard, a fresh row is inserted with level 1, 0 XP, 0 VICE, no slots, no stats, no training. They'll be prompted for an alias again.

To wipe just XP without losing the alias and ledger:

```sql
UPDATE heist_profiles SET level = 1, xp = 0 WHERE citizenid = 'ABC12345';
```

Cache will be stale until they reconnect — alternatively, push them off the server so `playerDropped` evicts them, or restart `cc_heistcontracts` to flush the entire cache.

## Recovering a stuck active slot

If a heist fails to call `FinishContract` (resource crashed, third-party heist doesn't integrate cleanly), a player can end up with a permanently "active" slot they can't start or discard. Since `activeSlot` is in-memory only, the easiest fixes are:

- **Have the player rejoin** — `playerDropped` evicts their profile from the cache, and on reconnect they come back with `activeSlot = nil`.
- **Restart `cc_heistcontracts`** — clears the in-memory cache for every player. Heavy-handed; only do this if multiple players are stuck.
- **Use the dashboard's Give Up button** — if the heist resource doesn't implement `CancelHeist`, the give-up path falls back to freeing just the abandoner's slot locally. The player sees a toast explaining this.

## Debug logging

`config.debug = true` in `shared/config.lua` toggles `[DEBUG]` lines from `utils.dprint`. Default is on. Useful lines you'll see:

- `[DEBUG] listing added: <contractId> (N/max)` — every time the drip thread successfully adds a listing.
- `[DEBUG] listings expired: N removed, M remain` — every expiry sweep that finds something to cull.
- `[DEBUG] entry_point error for <id>: <msg>` — when a contract's entry point throws on Start. The active-slot mark is rolled back when this happens.
- `[DEBUG] reset error for <id>: <msg>` — when a contract's cooldown `reset` callback throws.
- `[DEBUG] Profile.GetBySrc: no citizenid for src <n>` — citizenid lookup failed (usually means the player isn't fully loaded into the core yet).

Server prints (not gated by `debug`) also include:

- `[cc_heistcontracts] CancelHeist threw for <resource>: <msg>` — a heist resource's `CancelHeist` export raised an exception during a give-up flow.

For production, flip `config.debug = false`. Server prints only happen on actual failures after that.
